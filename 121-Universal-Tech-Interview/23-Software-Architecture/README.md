# 23 - Software Architecture

> System-level design decisions: patterns, layering, and trade-offs.

## What It Covers

- **Patterns**: Monolith, Modular Monolith, Microservices, Serverless, Event-Driven, Layered, Hexagonal, Clean, DDD
- **Concepts**: Coupling/Cohesion, CAP, Consistency vs Availability, Distributed Transactions (Saga, Outbox), Event Sourcing, CQRS
- **Quality**: Scalability, Maintainability, Testability, Reliability

## Sample Interview Questions

1. Monolith vs microservices — when do you choose each?
2. What is Domain-Driven Design and bounded context?
3. Explain CQRS and when to use it.
4. What is event sourcing? Trade-offs?
5. How do you handle distributed transactions?
6. Explain the layers of a clean architecture.
7. How do you evolve architecture as a startup scales?

## Prep Tips

- Know the "when to use" and trade-offs for each pattern — not just definitions.
- Be ready to defend a monolith as a valid early choice.
- Connect patterns to real projects in your resume.
